# Friday demo, 2026-11-13: the week in mansio

What moved in mansio from 2026-11-06 to 2026-11-13, by theme, with steps you can run.
You need a checkout of this repository, the Rust toolchain pinned in `rust-toolchain.toml`, `curl` and `jq`. No Docker.

## This week

- mansio now runs on the current Iggy: server 0.10 with SDK 0.12. Iggy server 0.9 is no longer supported, so an operator upgrades Iggy and mansio together.
- A release now checks itself before the owner is asked to approve: the state models must hold, and the run lists which demos cover the release.
- The first release is still blocked. The release pull request does not open: the token fix landed, and the run now stops on a setting in `release-plz.toml` that the tool does not know.
- An automated reviewer (Greptile) reads every pull request and comments on defects only. Each comment must be resolved before the merge.
- The contributor writing rule was rewritten: fewest words, simple code explains itself.
- Routine updates: the image base, the CI actions, two crates.

Numbers: 13 pull requests merged, 0 releases cut, 3 issues closed.

Biggest risk: mansio has never been released. Every push to `main` this week ended with a failed [release run](https://github.com/ShozanHQ/mansio/actions/workflows/release.yml), so the release path is still unproven end to end.

## The steps

### 1. Start the server

Run this in one terminal. CI starts the same server itself.

```sh
cd mansio
export MANSIO_DEMO_DIR=$(mktemp -d)
MANSIO_BROKER=memory MANSIO_TOKEN=demo-token MANSIO_SINK_PATH="$MANSIO_DEMO_DIR/sink.jsonl" \
  MANSIO_SNAPSHOT_DIR= cargo run -p mansio-server
```

In a second terminal, for every step after this one:

```sh
cd mansio
cargo build -p mansio
export PATH="$PWD/target/debug:$PATH" MANSIO_URL=http://127.0.0.1:7070 MANSIO_TOKEN=demo-token
```

### 2. The bus still answers after the broker move

Nothing in the HTTP API or the CLI changed this week. This confirms a publish and a read still work.

```bash
curl -fsS "$MANSIO_URL/healthz"
mansio publish --tenant demo --topic facts.build --type build.finished \
  --source ci --data '{"sha":"abc"}' | jq -e '.type == "build.finished"'
mansio poll --tenant demo --topic facts.build | grep -F '"sha":"abc"'
curl -fsS -H "Authorization: Bearer $MANSIO_TOKEN" "$MANSIO_URL/metrics" \
  | grep -Fx 'mansio_published_messages_total{tenant="demo",topic="facts.build"} 1'
```

You should see the health answer, `true`, the stored envelope, and the counter at 1:

```text
{"status":"ok"}
true
mansio_published_messages_total{tenant="demo",topic="facts.build"} 1
```

### 3. mansio is pinned to the Iggy 0.10 pair

The SDK and the server image move together. Both pins are in the checkout:

```bash
grep -F 'iggy = "=0.12.0"' Cargo.toml
grep -o 'apache/iggy:0.10.0@sha256' compose.yaml
```

```text
iggy = "=0.12.0"

```

The move itself needs a running Iggy, so CI shows it: the [`e2e` job on `main`](https://github.com/ShozanHQ/mansio/actions/runs/43467229306/job/132029491339) runs the full suite against Iggy server 0.10 and is green. On Linux with Docker, `docker compose up --build --wait` starts the same stack.

### 4. A release names its walkthroughs

This is what the owner reads in the release run's summary before approving `publish`.

```bash
bash .github/scripts/release-walkthroughs.sh | tee "$MANSIO_DEMO_DIR/walkthroughs.md"
grep -F '## Walkthroughs since' "$MANSIO_DEMO_DIR/walkthroughs.md"
```

In a full clone you should see one line per demo with a diffmap link and the pull requests it covers, then `In no walkthrough:` with the rest. Once this file is on `main`, this week's pull requests move from the second list to a line of their own.

### 5. A release checks the state models first

The same command the new `before` job runs on the release commit. It takes a minute to build, so CI's `check` job runs it, not this demo.

```sh
cargo test -q --locked -p mansio-models
```

You should see `test result: ok` for 6 and for 12 tests. A failure here stops a release before anything is published.

## Architecture

```mermaid diff [The broker pair and the release gate]
 flowchart LR
     S[mansio-server] --> I[mansio-iggy]
-    I -->|SDK 0.11, protocol 0.11| B9[Iggy server 0.9]
+    I -->|SDK 0.12, protocol 0.12| B10[Iggy server 0.10]
     P[release: prepare]
-    P --> PUB[publish crates]
+    P --> BEF[before: state models, walkthrough list]
+    BEF --> PUB[publish crates]
     PUB --> T[signed tag]
     %% ref node:I [[crates/mansio-iggy/src/broker.rs]]
     %% ref node:BEF [[.github/workflows/release.yml]]
```

- Dependency and protocol: the `iggy` SDK goes from 0.11 to 0.12 and the server from 0.9 to 0.10, because an SDK only talks to servers of its own protocol version. mansio supports one protocol version at a time.
- Release pipeline: a `before` job sits between `prepare` and `publish`, because a release does not wait for CI on its commit.
- Review: Greptile is a new outside service on every pull request, configured in `.greptile/`, which is a code-owner path.
- No new crate, service, data path or setting.

## What moved

### mansio runs on the current Iggy

mansio moved to the released pair for Iggy's binary protocol 0.12: SDK 0.12.0 and server 0.10.0. Someone running mansio upgrades the Iggy server in the same step, because the new build does not talk to server 0.9. The week showed why: an automated bump of the image alone broke the stack and was rolled back the same day, then both halves moved together. The code change is small, the SDK's new call shapes behind one helper, [[5008516:crates/mansio-iggy/src/broker.rs#L49-L55]], and the image is pinned by digest, [[5008516:compose.yaml#L78-L82]]. (#91, #84, #74)

### A release checks itself before the owner approves

The release run now has a `before` job, [[584b21c:.github/workflows/release.yml#L144-L165]]. It runs the state models on the release commit and writes the list of demos that cover the release into the run summary, built by [[.github/scripts/release-walkthroughs.sh]]. The owner reads one summary, not a diff, before the first approval. The release pull request also got the git token it lacked. It still does not open: the run stops on `conventional_commits` in [[release-plz.toml]], which this version of release-plz rejects. (#90, #89)

### An automated reviewer reads every pull request

Greptile now reviews each pull request, set to comment only on wrong behaviour, security holes and lost data: [[.greptile/config.json]]. Each comment is a review thread, and a pull request merges only when every thread is resolved, so a real finding cannot be skipped. The contributor guide says so, and its writing rule is now three short lines: [[CONTRIBUTING.md]]. (#87, #81)

### Dependencies kept current

The image base, three CI actions and two crates moved to their newest versions. One of them drops an unmaintained crate from the tree. Nothing here changes behaviour. (#73, #75, #76, #77, #79, #80)
